# منصة الفعاليات — Events Platform

منصة تربط **العملاء الباحثين عن فعاليات** بـ**أصحاب الفعاليات (المنظمين)**:

| الجزء | لمن | التقنية |
|---|---|---|
| `apps/mobile` | تطبيق العميل (iOS / Android) | React Native + Expo Router |
| `apps/web` | لوحة الأدمن + لوحة المنظم + صفحة الدفع + الـ API الذي يخدم التطبيق | Next.js 15 (App Router) + Tailwind |
| `packages/db` | قاعدة البيانات (المخطط، الترحيلات، البيانات الأولية) | Prisma + PostgreSQL |
| `packages/shared` | منطق مشترك: الحسابات المالية، سياسة الاسترداد، التحقق من المدخلات | TypeScript + Zod |

الواجهات كلها **ثنائية اللغة (عربي/إنجليزي)**، والاتجاه يتبدل تلقائياً: RTL للعربي و LTR للإنجليزي.

## الميزات

### تطبيق العميل
- تسجيل ودخول بالبريد وكلمة المرور، واستعادة كلمة المرور.
- الرئيسية: الفعاليات المميزة، والقريبة منك، والقادمة.
- البحث بالاسم والتصفية حسب المدينة والتصنيف والتاريخ والسعر.
- خريطة للفعاليات القريبة من موقعك.
- صفحة الفعالية فيها التفاصيل والمنظم وتقييمه وأنواع التذاكر وسياسة الاسترداد والتقييمات.
- الشراء والدفع عبر Moyasar: مدى، فيزا، ماستركارد، STC Pay.
- تذاكري: تذاكر QR لكل تذكرة، وإيصال يوضح ضريبة القيمة المضافة 15%، وطلب استرداد حسب سياسة المنظم.
- المفضلة، والتقييم بعد الحضور (يُسمح فقط لمن مُسحت تذكرته)، والإشعارات.

### لوحة المنظم (ويب)
- تسجيل جهة مع السجل التجاري والآيبان، ثم انتظار موافقة الأدمن.
- إنشاء الفعاليات بلغتين مع صور وموقع على الخريطة وأنواع تذاكر متعددة وسياسة استرداد، ثم إرسالها للمراجعة.
- بعد النشر: زيادة الكميات، وتعديل فترة البيع، وإضافة أنواع جديدة. أسعار الأنواع الموجودة لا تتغير.
- المبيعات والحضور وقائمة المشترين وتصدير CSV.
- إلغاء الفعالية يسترد مبالغ جميع الطلبات المدفوعة تلقائياً ويرسل إشعاراً للعملاء.
- الرصيد: المبيعات والعمولة والصافي والتحويلات المستلمة.
- حسابات موظفين صلاحيتهم مسح التذاكر فقط.
- صفحة مسح QR بكاميرا الجوال من المتصفح، مع إدخال يدوي احتياطي.

### لوحة الأدمن (ويب)
- إحصائيات المبيعات والعمولات والضريبة ومستحقات المنظمين.
- مراجعة المنظمين: اعتماد، رفض مع سبب، إيقاف، وتحديد **نسبة العمولة لكل منظم**.
- مراجعة الفعاليات: اعتماد أو رفض مع سبب، و**تمييز يدوي** مع تاريخ انتهاء اختياري، وإلغاء.
- الطلبات، والاستردادات (مع إعادة محاولة الفاشل)، والتحويلات اليدوية للمنظمين وتسجيلها.
- إرسال إشعارات Push للجميع أو حسب المدينة أو التصنيف، وكل عميل يستقبلها بلغته.
- العملاء (عرض وإيقاف)، والتصنيفات، والمدن، وبيانات الإيصال ونسبة الضريبة.

### إشعارات تلقائية
تأكيد الشراء، وتذكير قبل الفعالية بـ 24 ساعة، وإلغاء الفعالية، والاسترداد.

## الحسابات المالية

- السعر الذي يدخله المنظم **شامل ضريبة القيمة المضافة**.
- الضريبة = الإجمالي × 15 / 115.
- **العمولة = نسبة المنظم × المبلغ قبل الضريبة**.
- صافي المنظم = الإجمالي − العمولة.
- النسب تُحفظ مع كل طلب، فتغيير نسبة العمولة أو الضريبة لا يؤثر على الطلبات السابقة.
- كل المبالغ تُخزن بالهللة (عدد صحيح) لتجنب أخطاء الكسور.

مثال: تذكرتان بـ 115 ريال، والعمولة 12%:
- الإجمالي 230، والضريبة 30، والمبلغ قبل الضريبة 200.
- العمولة 24، وصافي المنظم 206.

## التشغيل محلياً

المتطلبات: Node.js 22، و pnpm 10، و PostgreSQL 14 أو أحدث.

1. ثبّت الحزم:

```bash
pnpm install
```

2. أنشئ ملفات الإعدادات وعدّل القيم (قاعدة البيانات والأسرار). محلياً `DATABASE_URL_UNPOOLED` هو نفس `DATABASE_URL`:

```bash
cp apps/web/.env.example apps/web/.env
```

```bash
cp apps/web/.env packages/db/.env
```

3. أنشئ الجداول:

```bash
pnpm db:deploy
```

4. أنشئ حساب الأدمن والمدن والتصنيفات. أضف `SEED_DEMO=1` إذا أردت بيانات تجريبية:

```bash
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='StrongPass123' pnpm db:seed
```

5. شغّل الويب (اللوحات + الـ API):

```bash
pnpm dev:web
```

افتح http://localhost:3000/ar أو http://localhost:3000/en

6. شغّل المهام الدورية في نافذة أخرى. تنهي الطلبات غير المدفوعة بعد 15 دقيقة، وتغلق الفعاليات المنتهية، وترسل تذكير الـ 24 ساعة:

```bash
CRON_SECRET=dev-cron pnpm --filter @events/web cron
```

### تطبيق الجوال

```bash
cp apps/mobile/.env.example apps/mobile/.env
```

ضع في `EXPO_PUBLIC_API_URL` عنوان جهازك في الشبكة، مثل `http://192.168.1.10:3000`، ثم:

```bash
pnpm dev:mobile
```

- الخريطة والإشعارات تحتاج **Development Build**، أنشئه بـ `npx expo run:ios` أو `npx expo run:android` أو عبر EAS Build.
- للإشعارات: أنشئ مشروعاً على EAS ثم ضع الـ `projectId` في `apps/mobile/app.json` تحت `extra.eas.projectId`.
- لخرائط Android: ضع مفتاح Google Maps في `android.config.googleMaps.apiKey` داخل `app.json`.
- اسم التطبيق ومعرّف الحزمة (`com.example.events`) في `app.json` قيم مؤقتة يجب تغييرها قبل النشر في المتاجر.

## ربط Moyasar

1. من لوحة Moyasar خذ المفاتيح وضعها في `apps/web/.env`:
   - `MOYASAR_PUBLISHABLE_KEY` و `MOYASAR_SECRET_KEY` (مفاتيح test أولاً ثم live).
2. أضف Webhook على العنوان التالي، وضع نفس الـ secret token في `MOYASAR_WEBHOOK_SECRET`:

```
https://YOUR_DOMAIN/api/webhooks/moyasar
```

3. `APP_URL` يجب أن يكون العنوان العام للموقع، لأن Moyasar يعيد العميل إلى `APP_URL/api/payments/moyasar/callback`.

مسار الدفع:
- التطبيق ينشئ الطلب، وتُحجز التذاكر لمدة 15 دقيقة.
- تُفتح صفحة الدفع داخل التطبيق، ويدفع العميل عبر نموذج Moyasar.
- الخادم يتحقق من الدفع مباشرة من Moyasar (المبلغ والعملة ورقم الطلب) قبل إصدار التذاكر.
- الـ Webhook احتياط إذا أغلق العميل التطبيق أثناء الدفع.

**بدون مفاتيح Moyasar** في وضع التطوير تظهر صفحة محاكاة للدفع (نجاح أو فشل) للتجربة فقط. لا تُفعَّل في الإنتاج إلا إذا ضُبط `MOYASAR_MOCK=1`، وهذا مخصص للاختبارات الآلية ولا يُستخدم أبداً في الإنتاج الفعلي.

> **ملاحظة عن Apple Pay:** صفحة الدفع تعمل داخل WebView في التطبيق، وApple Pay لا يعمل داخل WebView على iOS. لذلك المتاح داخل التطبيق: مدى وفيزا وماستركارد وSTC Pay. إضافة Apple Pay داخل التطبيق تحتاج حزمة Moyasar الأصلية لـ React Native، وهي خطوة منفصلة.

## النشر على Vercel

الويب (اللوحات + الـ API + صفحة الدفع) جاهز للنشر على Vercel. الإعدادات في `apps/web/vercel.json`:
- التثبيت من جذر المشروع.
- توليد Prisma وتطبيق ترحيلات قاعدة البيانات تلقائياً مع كل نشر.
- مهمة دورية يومية الساعة 6 صباحاً بتوقيت الرياض.

### الخطوات (مرة واحدة)

1. في Vercel: **Add New → Project** واستورد المستودع `mjaljassir-cmd/FRH`.
2. في إعدادات الاستيراد غيّر **Root Directory** إلى `apps/web`. يتعرّف Vercel على Next.js تلقائياً، ولا تغيّر أوامر البناء.
3. قبل الضغط على Deploy افتح **Environment Variables** وأضف:

| المتغير | القيمة |
|---|---|
| `JWT_SECRET` | قيمة عشوائية طويلة |
| `QR_SECRET` | قيمة عشوائية طويلة (لا تغيّرها بعد الإطلاق) |
| `CRON_SECRET` | قيمة عشوائية طويلة |
| `APP_URL` | رابط المشروع، مثل `https://frh.vercel.app` (حدّثه بعد أول نشر إن تغيّر) |
| `MOYASAR_PUBLISHABLE_KEY` / `MOYASAR_SECRET_KEY` / `MOYASAR_WEBHOOK_SECRET` | من لوحة Moyasar |
| `SMTP_*` | اختياري، لرسائل استعادة كلمة المرور |
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | اختياري، لخريطة اختيار الموقع |

لتوليد قيمة عشوائية:

```bash
openssl rand -hex 32
```

4. اضغط **Deploy**. أول نشر سيفشل لأن قاعدة البيانات غير موجودة بعد، وهذا متوقع.
5. من تبويب **Storage** في المشروع:
   - أضف **Neon (Postgres)** واربطه بالمشروع. يضبط `DATABASE_URL` و `DATABASE_URL_UNPOOLED` تلقائياً.
   - أضف **Blob** واربطه بالمشروع. يضبط `BLOB_READ_WRITE_TOKEN` تلقائياً.
6. من **Deployments** اضغط **Redeploy**. هذا النشر ينشئ الجداول ويشغّل الموقع.
7. أنشئ حساب الأدمن والمدن والتصنيفات مرة واحدة من جهازك. انسخ قيمة `DATABASE_URL_UNPOOLED` من إعدادات Vercel، ثم:

```bash
DATABASE_URL="<الرابط>" DATABASE_URL_UNPOOLED="<الرابط>" ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='StrongPass123' pnpm db:seed
```

8. في لوحة Moyasar أضف Webhook على `https://<رابطك>/api/webhooks/moyasar`.
9. في تطبيق الجوال اجعل `EXPO_PUBLIC_API_URL` رابط Vercel نفسه.

### ملاحظات Vercel
- **رفع الملفات:** الصور وملفات السجل التجاري تُرفع من المتصفح مباشرة إلى Vercel Blob، ولا تمر بالسيرفر. السبب أن Vercel يرفض الطلبات الأكبر من 4.5 ميجا. الحد لكل ملف 5 ميجا.
- **الطلبات غير المدفوعة:** في الخطة المجانية (Hobby) المهمة الدورية تعمل مرة يومياً فقط. لذلك التذاكر المحجوزة لطلب لم يُدفع تُحرَّر تلقائياً بعد 15 دقيقة عند أول محاولة شراء أو فتح للفعالية، دون انتظار المهمة. التذكير قبل الفعالية يُرسل في تشغيل الصباح لكل فعالية تبدأ خلال 24 ساعة.
- **روابط الملفات:** ملفات السجل التجاري في Blob لها روابط عشوائية طويلة لا يمكن تخمينها، لكنها ليست محمية بكلمة مرور. من يملك الرابط يستطيع فتحها، والرابط يظهر للأدمن فقط.
- **الخطة المجانية:** Hobby مخصّصة حسب شروط Vercel للاستخدام غير التجاري. للبيع الفعلي للتذاكر قد تحتاج خطة Pro.

### بدون Vercel (أي سيرفر Node.js)
- البناء بـ `pnpm build:web` ثم التشغيل بـ `pnpm --filter @events/web start`.
- نفّذ `pnpm db:deploy` عند كل نشر.
- شغّل `scripts/cron.mjs` للمهام الدورية.
- بدون `BLOB_READ_WRITE_TOKEN` تُحفظ الملفات على قرص السيرفر في `apps/web/uploads`.

## الاختبارات

```bash

MOYASAR_MOCK=1 pnpm --filter @events/web start

```

السيناريو الذي يغطيه:
1. تسجيل منظم، ثم موافقة الأدمن وتحديد العمولة.
2. إنشاء فعالية، ثم اعتمادها وتمييزها.
3. تسجيل عميل وشرائه تذاكر، مع التحقق من منع البيع الزائد عند الطلبات المتزامنة.
4. الدفع، ثم مسح QR مرتين (الثانية مرفوضة)، وتجربة رمز QR معدّل.
5. التقييم، والاسترداد حسب السياسة.
6. حساب موظف، والرصيد.
7. إلغاء الفعالية واسترداد الجميع.
8. التحقق من اتجاه RTL و LTR.

## هيكل المشروع

```
apps/web/src/
  app/[locale]/admin/        لوحة الأدمن
  app/[locale]/organizer/    لوحة المنظم + صفحة المسح
  app/[locale]/pay/          صفحة الدفع (تُفتح داخل التطبيق)
  app/api/v1/                API تطبيق الجوال
  app/api/webhooks/moyasar   Webhook الدفع
  app/api/cron               المهام الدورية
  lib/orders.ts              منطق الطلبات والدفع والاسترداد والإلغاء
  lib/checkin.ts             التحقق من التذاكر عند البوابة
apps/web/messages/           ترجمات الويب (ar.json / en.json)
apps/mobile/app/             شاشات التطبيق
apps/mobile/src/i18n/        ترجمات التطبيق (ar.ts / en.ts)
packages/db/prisma/          مخطط قاعدة البيانات والترحيلات
```

### اللغة والاتجاه
- **الويب:** الروابط `/ar/...` و `/en/...`، والوسم `<html dir>` يتغير حسب اللغة. التصميم يستخدم خصائص منطقية (`ms-`/`me-`/`start`/`end`) فينعكس تلقائياً.
- **التطبيق:** يبدأ بلغة الجهاز، ويمكن تغييرها من «حسابي». عند التغيير يُعاد تشغيل التطبيق ليتبدل الاتجاه، وهذا شرط في React Native.
- **المحتوى:** الفعاليات والتصنيفات والمدن وأنواع التذاكر والإشعارات تُخزن بلغتين.
